❯ some context for this project and for the claude md.                          
  A travel agent planning a trip wants to know what is on in a place while      
  their traveller is there: a festival, a concert,                              
  a big match, a market. Build a first version of a feed that collects those    
  events for Hermanus, South Africa, so that the people and                     
  the agents planning trips can use it.                                         
  Some context on how it gets used. A luxury trip is usually booked 6 to 18     
  months before it starts. Closer to the date the trip is refined               
  and activities are booked, so a planner looks at the same place more than     
  once, months apart. Travellers also vary widely in age and                    
  interests, so what is worth knowing about differs from one trip to the next.  
  What counts as an event                                                       
  Something to go to: J. Cole in Johannesburg on 12 December 2026, Lions v      
  Munster at Ellis Park on 17 April 2027, the Hermanus                          
  Country Market on a Saturday.                                                 
  Something that runs: a theatre show with 81 dates, an exhibition that is open 
  for a year.                                                                   
  Something months away: the FynArts Festival in Hermanus in June 2027.         
  A season, which has months and no date: southern right whales off Hermanus,   
  June to November.                                                             
  What we want in a solution                                                    
  1. Data model design. Work out the problem, then how to model the domain.     
  2. API design. Expose that model as an agent-friendly set of APIs.            
  3. Agents working through those APIs. Get a normal Claude or Codex to use the 
  API and do the data processing.                                               
  4. Pen and paper notes. We want to see literal pen and paper notes on the     
  design.

  goes we're going with hono for the api, sqlite for the db eventthough         
  postgress would be best for prod. as far as testing and verification go,      
  tests are mainly end to end, we dont need unit tests for this. we'll need a   
  gold set of events that I will provide. create the md file so i can review.

  into dev. It describes the venue lookup like this:

  - Lookup: In production, the processing agent looks up a venue with the Google
    Maps Places API when the source gives no town.

    boundary of the place. A venue inside the boundary keeps a high confidence.
    A scan for a venue outside it is ignored with a reason. If the lookup finds
    no match or more than one match, the event goes to review.
